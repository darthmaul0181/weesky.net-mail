### The settings module

**Settings module** — `SettingsLayout` (`src/modules/settings/SettingsLayout.tsx`) renders a `.context-pane` of `NavLink`s beside a `.settings-content` `<Outlet/>`, **grouped by module**: Account / Appearance / Sync with no heading, then **Mail** (General / Connected accounts / Folders / Identities / Aliases / Rules), **Calendar** (General) and **Application** (Administration / About) — Account and Aliases shown only for the primary account, Sync whatever the active account once the deployment publishes an address (its secret, address book and calendars are the Scotty user's, not the mailbox's), Administration to an admin whatever the active account, Rules requiring the primary account or a Sieve-capable domain. A group is a `role="group"` named by its `.pane-group-label`, drawn in full ink rather than `--text-muted`: measured off the palette files, muted on `--folders-bg` stays under 4.5:1 in six light palettes. Sync is ungrouped because it syncs the calendars and the address book alike. **Two groups each hold a General**, so each of those pages carries its module as an eyebrow over the shared title (`PreferencePage`), and the phone bar reads `Mail · General` / `Calendar · General`. `/settings/general` redirects to `/settings/mail`, where it always began, and the gates that used to send a refused page there send it to `/settings/mail` too. **Each row carries the icon its own page's title carries** — `UserIcon`, `SlidersIcon`, `PersonPlusIcon`, `DropletIcon`, `FolderIcon`, `AtSignIcon`, `MailIcon`, `FunnelIcon`, `ShieldIcon`, `InfoIcon` — which is the site's trigger/title continuity rule, not a free choice: changing one without the other is the drift the rule exists to prevent. The icon takes `currentColor`, so the active row's foreground carries it, and `flex: none` keeps it from shrinking to buy the label a few pixels. **The 200px column leaves 134px of text once the icon and its gap are taken, and that number was read off a browser rather than computed.** Four things spend the other 66 — the pane's `border-right` and its padding, the row's own padding, the icon, and the gap between the icon and the label — and the arithmetic is easy to get wrong in the roomy direction: a previous note here claimed 155, having dropped both the row's padding and the border, and read the nav as having 24% of headroom. Re-measure it (`probes/localisation-widths.html`, below) rather than re-deriving it. The widest label the tree can draw is English `Connected accounts` at **128px** in the active row's 600 weight (125.4 at 400, which is where the old note's "125" came from) — **six pixels of headroom, not thirty**. French is the shorter of the two languages here: `Comptes connectés` spends 124px active, `Administration` is byte-identical in both, and nothing else clears 70. So the nav fits English and French and has almost nothing left for a third: a label past 134px wraps, and **the fix is the column width rather than the icons** — the icon/title continuity rule above is load-bearing and 200 is not. Module directories under `src/modules/settings/`:
- `general/` — one General page per module over one frame: `PreferencePage.tsx` (eyebrow, title, load and failure states, toasts) and `useSavePreference.ts` (one write, confirmed or refused by a toast). `CalendarGeneralPage.tsx` holds **Calendars** (the birthdays calendar, written through its own route since switching it creates or removes a calendar) and **Week** (the first day of the week). `MailGeneralPage.tsx` is grouped under `.account-section` headings rather than run as one list: **Message list** (reading pane, messages per page, message-list preview, conversation grouping, folder icons, the quick-action picker), **Swipe gestures**, **Privacy & security** (always-show-remote-images with always-show-images-from-contacts nested under it, spam-score visibility), **Composing** (default editor, then save-new-recipients; the heading is where a signature and a reply-quoting rule will land), **Notifications** (new-mail sound, desktop notification, plus the three mutually exclusive permission notes, which stay conditional because they are state rather than description). The headings are Appearance's, so the two settings pages group alike instead of in two dialects. **The quick-action picker is toggle chips (`.action-chips`), deliberately not the `.layout-card` skin the reading pane uses two rows above it**: one control taking several answers drawn exactly like one taking a single answer is separated from it by a 12px box against a 12px disc. The chip is a `<button aria-pressed>` — the `--action-primary` fill *is* the state, so there is no box to tick, and `aria-pressed` is what carries that to anything not looking at the colour

**The default editor is `mail.composeFormat` (`html`|`text`, default `html`) and it governs every composer but a resumed draft** — new, reply, reply-all, forward and edit-as-new all take it, because answering a mailing list is the case plain text exists for and it is the one `composeSeed.ts` used to force into HTML by writing `text: null` literally three times. `applyComposeFormat` (`compose/composeSeed.ts`) is where it is applied, once, in a `useMemo` with an empty dependency list so changing the setting never reformats a message being written. **Its carve-out tests `seed.action === 'draft'`, never `seed.text`**: an HTML draft carries `text: null` exactly like a reply, so a body test cannot tell them apart and would throw the draft's body away — the same boundary `ComposeView` draws for its dirty flag. Clearing each attachment's `contentId` is the whole of the inline-image handling, since the composer already splits the seed's attachments on that field. A `mailto:` needs no case of its own: `mailtoSeed` declares itself `editAsNew`. **`ComposeView` renders `LoadingBlock` until preferences arrive** (a failed load shows Retry and Close, Close returning wherever the composer's own exits would), which nothing else in that file needed — `captureRecipientsOf` is read at send time, this is read at mount, and without the gate the composer opens in HTML and flips to a textarea under whoever has started typing. That gate is also why `ComposeView.test.tsx` primes the query cache from a module-level `prefs` rather than letting the api mock resolve asynchronously: 84 tests queried the DOM against the spinner otherwise. The preference path never reaches the `losesFormatting` confirm dialog — the choice was already made in Settings, and asking again on every reply is noise
- `account/` — `AccountPage.tsx` (identity, other domains, quota via `QuotaBlock`, `ChangePasswordSection.tsx`)
- `appearance/` — `AppearancePage.tsx` (theme + palette radio groups, backed by `ThemeContext`). Each palette card carries a thumbnail that **declares the palette it advertises** rather than the active one, and a hover-revealed loupe opening the same preview enlarged, in **both** modes at once — the thumbnail can only ever show the mode in use, and a palette is picked once for both. Two things are load-bearing: the loupe sits **outside** the card's `<label>`, since inside one a click on it activates the label's radio and asking to look at a palette would apply it; and the preview's every length is a multiple of one `--pp` scale, so `.is-large` changes that number alone and the two sizes cannot drift. The preview shows the compose button and the attachment chip because both carry `--action-primary` — without them twelve palettes read as twelve greys. **A ninth card is the account's own palette**: a dashed "Create my palette" until one exists, then a card like the others with a pencil at its top-left corner — the top-right is the loupe's, and their touch insets would overlap side by side. `CustomPaletteEditor` sets four things — structure hue, its intensity, accent hue, and whether the light-mode buttons wear the structure or the accent (dark ones wear the accent either way, which is why the label names light mode) — and previews the draft in both modes through `PalettePreview`'s `tokens` prop, inline properties that win over the attributes, so the draft never touches the saved palette's `<style>`. It opens on the saved palette, else on `PALETTE_SEEDS` for the active one. Save writes `ui.customPalette` and selects `custom` on this device only; a refusal keeps the dialog open with its message. There is no delete: leaving the palette is choosing another card
- `mail/` — `FoldersPage.tsx` (everything about folders in one place: the full list via `FolderManager`, plus the two dialogs that act across the whole set) and `SystemFoldersModal.tsx` (system role assignment; the selects exclude the inbox, non-selectable folders, and folders already overridden for another role)
- `aliases/` — `AliasesPage.tsx` (alias CRUD: the domain select, the search-or-create field), `AliasIndex.tsx` (the index itself) and `aliasFamilies.ts` (its grouping, pure). **Names are drawn as an index, never as tiles**: a line per letter, and a line of its own for every **family** — three aliases or more sharing the start up to their first `_`, `.` or `-` (`FAMILY_MIN`), the prefix written once as a chip and the names after it shown without it. Everything is shown and copied in lower case, since the mail server matches addresses without case; delete still sends the name as stored. The index is a `useGridNav` grid under `cellEntry` — one tab stop, the arrows walk the names, F2 reaches a name's copy and delete, Escape comes back — and each name's actions float in a bubble over its neighbours (`website-design.md`'s one exception to reserved space). **The grouping file is `aliasFamilies.ts` and not `aliasIndex.ts` on purpose**: on Windows' case-insensitive disk, `./AliasIndex` resolved to the `.ts` twin before the `.tsx`, and the component imported as `undefined`
- `identities/` — `IdentitiesPage.tsx` (the curated From list, styled as Administration tiles: each tile is `<display name> — <alias>` with a star to set the default, an edit button and a delete, sorted alphabetically by display name; the primary carries a `primary` tag and neither edit nor delete — its name is the live account FullName, patched in from `useAuth().identity` so an Account-tab change shows at once — and a stale identity carries an `unavailable` tag and a delete only) and `IdentityDialog.tsx` (the add/edit modal in the admin shape — `.field-h` rows, one `.btn-primary`, the three ways out; the alias field is a type-to-filter combobox like the virtual-domain owner picker over `useAliases()`, fixed once an existing identity is being edited). Every action `PUT`s the whole set — there is no per-row endpoint — so `IdentitiesPage` keeps an `edited` list of its own between actions: each mutation has to build on what the one before it produced, since the invalidation's refetch has not necessarily landed yet, and it is dropped the moment fresh server data arrives or a save is refused, so a refusal always leaves the page showing server state rather than an optimistic lie. **The page is keyed on the active account** (the default export is a one-line wrapper around `IdentitiesPanel`): a replace in flight blocks that drop, so without the key an optimistic list built from one mailbox survived a switch and the next star or delete PUT it over the other mailbox's set
- `accounts/` — `ConnectedAccountsPage.tsx`. **Sign in again is offered on every OAuth row, not only an invalid one**: `credentialsValid` says the stored cipher still opens, never that the provider still honours the token, so a revoked consent leaves the row looking healthy while the mailbox refuses. Re-consenting is idempotent and keeps the row's id, identities and roles.
- `rules/` — the Sieve rules manager, `RulesPage.tsx` being its composition (see below)
- `admin/` — `AdminPage.tsx` (tab bar: Accounts / Domains / Virtual domains / External domains / Application; the first three are withheld when `account.platform` is `generic`, read off `/api/Account` rather than the capabilities, which open an IMAP session) with `AccountsTab.tsx`, `DomainsTab.tsx`, `VirtualDomainsTab.tsx` (**not** `OwnershipTab` — renamed to match the `domains/virtuals` API and "virtual alias domain" terminology), `ExternalDomainsTab.tsx`, `ApplicationTab.tsx`, `AddEditUserModal.tsx`, `AddEditDomainModal.tsx`. The first three read `useAdminLists.ts`: one query per list under the shared `['admin']` root, so a tab returned to shows its cached list at once, and every write invalidates `onSettled` — a user or domain write the whole root, an owner change the virtual-domain list alone

- `about/` — `AboutPage.tsx`, the product card: the whole illustration, the name, the web and API versions, a copy-for-support button, the third-party licences and the copyright

**The product is called Scotty webmail, written in the code and never read from a setting.** `AboutPage` and `TopBar` spell it out; the administrator's `app.name` (Administration › Application, default `Scotty webmail`) names the browser TAB and the installed application, which is a different question — a deployment may want `Scotty (dev)` in the tab without renaming the product. `useTabTitle` reads it, mirrors it into `localStorage` under `app_name`, and `index.html` paints that mirror before React runs so the tab never flashes the hostname; the hostname is still the last resort, and the mailbox address still prefixes it. **One consequence for whoever runs the two deployments**: the hostname used to be the base title and told `account-dev` from production at a glance, and both now read `Scotty webmail` — give the dev instance an `app.name` of its own (`Scotty webmail (dev)`) or lose that signal.

**The About page is the one settings page that takes the whole content box** — `.settings-content:has(> .about-page)` drops that box's padding, so the layout never learns which route is open. Two consequences, both measured in `probes/mobile-layout.html`'s `settings-about` case rather than reasoned: the drawer's hamburger band bleeds out to that padding and has to have its negative margins cancelled with it (28px of overflow at 768 otherwise, 16 at 360), and the two text actions need the touch floor spelled twice — `var(--touch)` in the phone block and a literal 44px under `@media (hover: none)` for the touch tablet, where that token is not declared. The panel wears `--topbar-bg` with the band's own foregrounds: **`--rail-item-active` is not usable as text there** — measured off the palette files in Node, that accent falls to 2.36:1 on indigo's top bar and 2.37 on slate's, because it is a fill behind `--rail-item-active-fg`, never 13px text. The actions are `--topbar-fg` underlined, and the copyright is flat `--rail-fg` rather than a fade of it, which measured 3.55:1 on classic's light bar.

**The version is stamped at build time, and the two halves are reported apart.** `src/lib/appVersion.ts` carries what `vite.config.js` defines: `src/frontend/VERSION`, suffixed `-dev` in every mode but `production`, plus the short commit (`GITHUB_SHA`, else `git rev-parse`) and the build instant. The API answers its own, read from `src/scotty.microservice/VERSION`, through `GET /api/Version`: the two are numbered and deploy separately, there is no product-wide number, and a mismatch between them is exactly what the page exists to show; the page keeps reading when that call fails, saying "Server unavailable" rather than hiding the web half. The licences link points at `third-party-licenses.html`, a small page the build emits as a bundle **asset** — `rollup-plugin-license` collects the metadata and a plugin beside it renders and emits it, because writing the file to disk from that hook puts it there before Vite empties the output directory and deletes it. **It lists what is bundled, who wrote it and under which licence, and deliberately reproduces no licence text**: each row links the project, which carries its own, and `THIRD-PARTY.md` keeps the full notices in the repository. Our own borrowed assets (the RainLoop notification sound) are rows of the same table, declared in the config beside the collector.

**Every shipped icon comes out of `tools/brand/generate-icons.py`, from `assets/brand/scotty.png`.** By default `logo-192.png` serves the topbar, the apple-touch icon and the desktop notification and `favicon-32.png` is the tab icon — an administrator's logo replaces both through `useAppLogo` (the instance logo paragraph below); `public/icon-192.png` and `icon-512.png` the installed application; `scotty-720.webp` and `-1440.webp` the About page's illustration. The small icons crop the cat's head — the whole drawing is unreadable at 16px — inside a disc filled with `--pane-item-active-bg`'s cream, so it reads on a light tab strip and on the dark top bar alike. Every resize premultiplies alpha (`RGBa`), or the transparent black around the drawing bleeds into its edges. Replacing the artwork means re-running the script, never pointing a `<link>` at whatever an editor exported.
`rules/` files: `RulesPage.tsx` (the page: dialogs, toolbar, failure note), `useRulesData.ts` (the account-keyed query and every write), `RuleList.tsx` (the cards and their arrows, plus `useRuleDrag`, the drag by id, whose state the page holds so it outlives the list), `RuleCard.tsx`, `RuleEditorModal.tsx` (step wizard: name → conditions → actions → options), `RuleRows.tsx` (`ConditionRow`/`ActionRow`, and the field, operator and weekday label switches the card's summary reads too), `RuleHelpModal.tsx`, `ConvertConfirmModal.tsx`, `ruleDraft.ts` (the editor's rule and its validity checks), `ruleIcons.tsx` (the page's own icons). The rules query is read once per visit: `gcTime: 0` drops it on leaving and `staleTime: 'static'` stops every automatic refetch, which a failed load — no data, so stale whatever the `staleTime` number — would otherwise get on each focus and reconnect. The **Extended rules** toggle switches provider: ON = Weesky (native, full feature set), OFF = Rainloop (Snappymail-interop, restricted) — turning OFF runs `api.checkCompatibility` first and shows `ConvertConfirmModal` for rules that would be dropped. See the repo-root `DESIGN-rules.md`.

**The image of the day is two switches.** Administration › Application turns `app.dailyImage` on for the instance (`admin/DailyImageSection`), and only then does Appearance draw its own section (`appearance/DailyImageSection`), four `.seg` choices stored in `ui.dailyImage` on the account; switching the instance off hides the section and keeps each account's choice. The four labels are a `switch` over literal keys, never a key built from the style. The login page shows the photo whenever the instance is on, under the existing veil, its credit at z 0 so that on a short screen the card and its button stay on top.

**The instance logo is three PNGs drawn by the browser and never decoded by the API.** `LogoSection` (in `ApplicationTab`) takes one image, and `logoImage.ts` draws it into transparent squares of 32, 192 and 512 px, centred and never cropped, so an elongated logo keeps transparent margins; rasters are downscaled in steps, and an SVG with no intrinsic size is refused rather than guessed at. Its errors are normalised to two translation keys. The three are sent in one `PUT`, all or nothing: `AppLogo.Check` reads only the PNG signature, the IHDR size and a per-size weight cap (mirrored in `appLogo.ts` so an over-detailed image is refused before upload), because decoding user bytes on the server is attack surface the feature does not need. `GET` is anonymous (the login page wears it) and answers `image/png` with a one-year `immutable` cache, which is safe only because the address is versioned (`?v=` the `app.logo` value, a timestamp); `DELETE` brings Scotty back. **The response carries `Vary: Origin`**: the favicon loads the image with `crossOrigin='anonymous'` to draw its unread badge on it, and a copy cached from a plain, no-CORS load (the topbar's `<img>`) must never answer that one. `favicon.ts` drops a paint made for a previous logo and, when drawing the badge over the logo fails, falls back to the plain logo.

**`ApplicationTab` seeds its name fields during render, never from an effect, and reverts a refused field itself.** An effect runs after the commit, so the inputs were mounted empty for one frame and filled on the next; `findByLabelText` resolves on the commit that mounts the field, which on a loaded CI runner was that empty frame. A render-phase update re-renders before React commits, so no tree with an empty input is ever produced. The seed is keyed on the object React Query hands back, and structural sharing returns the same object when a refetch is deep-equal: a refused save that left the server unchanged reseeds nothing, so the catch block puts the field back. It reverts only the field whose own save failed — the two writes are sequential, and a refusal on the second leaves the first accepted.
