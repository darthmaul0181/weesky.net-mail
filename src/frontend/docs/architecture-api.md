### The API client

**API client** — `src/api.ts`: all backend calls go through `request()` and are exported as named methods on `api`. `BASE` is `import.meta.env.VITE_API_BASE`, with no built-in default: `vite.config.js` refuses to build without it, so a third-party installation that forgets `.env.production` fails the build rather than silently shipping requests to someone else's server.

Failures throw **`ApiError`**, which extends `Error` and carries `.status` and `.code`. The code is the backend's `ResultEnveloppe` message when it is a stable string — `credentials_unavailable`, `Message not found` — so callers branch on a symbol rather than on prose. `request()` accepts `{ signal }` for cancellation, which the message list relies on so that switching folders quickly cannot race a stale response into the UI. `requestBlob()` handles binary responses (attachments) and reads the file name from `Content-Disposition`. `mailAttachmentUrl()` builds the download URL so its encoding lives in one place. **Folder paths are always `encodeURIComponent`-encoded** — they may contain `/`, `&` or `#`.

**Every method returns the DTO its route answers, and no call site casts.** The shapes live beside the module that reads them (`mailTypes.ts`, `calendarTypes.ts`, `contactTypes.ts`, `adminTypes.ts`, `rulesTypes.ts`, the settings hooks), so `api.ts` stays transport plus signatures. `request<T>` resolves `null` on a 204, so a route that can answer one declares `| null`. And since the API omits a null field (`WhenWritingNull`), a field the server may leave empty is `?:`, never `| null`: a check against `null` on it would never fire.

**On `PUT /api/Contacts/{id}`, absent is not empty.** A field the request does not name is kept; an empty list or an empty string is still a clearing, an asked-for one. The rule does not cover the first name / last name / nickname trio or the addresses, which the editor always carries and where `null` is the user who emptied the box. Without it, the editor — which sends those five fields and nothing else — destroyed an imported card's phone number and birthday on the first edit to its name.
